# Research Log & Weekly Report

박사과정 연구일지 Notion 생성 + 당일 통계 + 주간 보고서 자동 정리.
요구사항 원문: `research-log/研究日记-需求交接.md`. 시간 보정 기록: `research-log/记忆本.md`.

## Notion 대상

- Daily Log: data_source `adc00f11-2f24-4085-99bc-e8277ee3cabd` (Research Home > Plan > 📒 Research Daily Log)
  - 속성: 기록(title), 날짜, 유형, 목적, 진행 내용, 결과 요약, 다음 액션, 관련 월, 일정(relation → 일정표), Project list
- 일정표 (Daily Goals): data_source `d1125ca6-ae4d-429e-a6b8-ced94703c477`
  - 속성: 오늘 목표(title), 날짜, 근무(전일/반일/불가), 프로젝트(select), 완료(checkbox), 예상 시간(h), 실제 시간(h), 메모, 일지(relation → Daily Log)
  - 일지.일정 ↔ 일정표.일지 는 양방향 relation. 한쪽만 설정.
- 계획 항목 (Plan Items): data_source `fc211540-a30e-4bc7-a5e8-3783017b70e2` (프로젝트×주차 셀, 주차 1–4)
- 월별 계획 (Monthly Plan): data_source `c640e1c7-dd2c-4ddb-b8d1-d8d5986d8c99`. 월 페이지는 `"월" = 'YYYY.MM'` SQL 조회.
- 주간 계획 DB `3c260e09-2cef-4bab-a610-9ccbd4de83b1`: 체크박스 달성률용. 보고서 생성 금지 (통계 왜곡).

## Daily Log 작성 절차

1. **당일 일정표 조회**
   ```sql
   SELECT url, "오늘 목표", "근무", "프로젝트", "완료", "예상 시간(h)", "실제 시간(h)"
   FROM "collection://d1125ca6-ae4d-429e-a6b8-ced94703c477"
   WHERE "date:날짜:start" = 'YYYY-MM-DD'
   ```
2. **실제 시간 확인 (필수, 일지 생성 전)**
   - `근무 ≠ 불가` 행 중 `실제 시간(h)` 비어 있는 행이 하나라도 있으면, 일지 만들기 전에 사용자에게 먼저 묻는다.
   - 행마다 목표명·예상 시간 보여주고 "실제 몇 시간? 완료했나요?" 질문. 답 받기 전 일지 생성 금지.
   - 답 받으면 일정표 행 업데이트: `실제 시간(h)` = 사용자 숫자, `완료` = 사용자가 완료라고 한 행만 `__YES__`.
   - 당일 일정표 행이 없으면 질문 생략. 통계는 "일정표 없음"으로 표기.
3. **직전 일지 다음 액션 조회** (아래 다음 액션 규칙).
4. **일지 생성**: 속성 + 본문(통계 섹션 포함). `일정` relation = 당일 일정표 행 URL 전부.
5. 일지 날짜보다 뒤 날짜 일지가 이미 있으면, 그 일지의 다음 액션도 새 일지 기준으로 이월 재계산 (속성 + 본문 체크리스트 둘 다).

## 당일 통계 (일지 본문에 기록)

대상: 당일 일정표 행 중 `근무 ≠ 불가`. 전부 불가면 "작업 불가일 — 통계 제외".

- 완료율 = 완료 체크 행 수 a / 대상 행 수 b → `n% (a/b)`, 정수 반올림. 목표 여러 개면 행별 집계.
- 예상 X h = Σ `예상 시간(h)`
- 실제 Y h = Σ `실제 시간(h)`
- 차이 = Y − X (부호 표기, 예 `+1.5 h` / `−2 h`)
- 사용자가 준 숫자만 사용. 빈 값 추정·창작 금지. 실제 시간 미입력 행 남으면 "실제 미입력 n건", 차이 생략.

본문 블록 (인용 첫 줄 바로 아래):

```
## 📊 오늘 통계

| 완료율 | 예상 | 실제 | 차이 |
| --- | --- | --- | --- |
| 50% (1/2) | 6 h | 7.5 h | +1.5 h |

| 오늘 목표 | 프로젝트 | 근무 | 완료 | 예상(h) | 실제(h) |
| --- | --- | --- | --- | --- | --- |
| ... | ... | 전일 | ✅ | 6 | 7.5 |
```

## Daily Log 규칙

속성:
- 기록(title): `MMDD 제목` (예 "0720 다중 사용자 필기 신호 수집")
- 날짜: 사용자 지정 날짜, 현재 연도
- 유형: 실험 / 분석 / 글쓰기 / 회의 / 기타 중 하나만
- 목적·진행 내용·결과 요약: 사용자 내용 요약
- 관련 월: 날짜 기준 월 페이지 자동 연결
- 일정: 당일 일정표 행 연결
- work list: 자동 입력 금지. 사용자 수동.

다음 액션 (중요):
1. 임의 생성·편집 금지. 사용자 발화만 기록.
2. 새 일지 전 직전 일지 다음 액션 SQL 조회.
3. 진행 확인된 항목 삭제. 미진행 항목 새 일지에 이월.

본문 형식:
- 첫 줄 인용: `> 📅 **YYYY-MM-DD (요일)** | 유형: X | 주제: Y`
- 📊 오늘 통계 → 진행 내용 표 (시간대 있으면 타임라인 표)
- 핵심 인사이트 💡 콜아웃. 다음 액션 체크박스. 아이콘 이모지.
- 언어 한국어 기본. 요청 시 영어/중국어.
- 숫자·조건·용어 원문 그대로. 데이터 창작 금지.

기타:
- 캘린더 일정 Google Calendar만. Notion 작성 금지.
- 미팅 정보 Gmail 검색해 확정 내용(일시/참석자/링크) 반영 가능.

## 시간 추정 보정

- 데이터: 일정표 중 `근무 ≠ 불가` 이고 예상·실제 둘 다 있는 행.
- 프로젝트별 비율 = Σ실제 / Σ예상, 표본 수 n.
- 갱신 시점: 주간 보고서 작성 시, 또는 사용자 일정 계획 요청 시. 결과는 `research-log/记忆本.md` 표에 기록 후 커밋.
- 적용: n ≥ 3 프로젝트만 이후 일정 예상 시간 = 기본 × 비율로 조정 제안. n < 3 이면 기본값 유지.
- 기본값 (가정): 전일 6 h / 반일 3 h.
- 비율은 제안만. 일정표 예상 시간 자동 변경 금지 — 사용자 확인 후 수정.

## Weekly Report 규칙

트리거: "주간 보고서" / "weekly report" / "주간 정리"

주차 기준: 월요일 시작. 월 안에서 5주차가 생기면 다음 달 1주차로 병합.

절차:
1. 주간 범위 Daily Log SQL 전체 조회:
   ```sql
   SELECT url, "기록", "date:날짜:start", "유형", "진행 내용", "결과 요약", "다음 액션"
   FROM "collection://adc00f11-2f24-4085-99bc-e8277ee3cabd"
   WHERE "date:날짜:start" >= 'YYYY-MM-DD' AND "date:날짜:start" <= 'YYYY-MM-DD'
   ORDER BY "date:날짜:start"
   ```
2. 다음 액션 추적: 이후 일지에서 진행 확인 = ✅ 완료. 미확인 = ❓. 추측 금지.
3. 완료율 = 확정 완료 / 전체 (%). ❓ 항목 "확인 후 업데이트 필요" 명시.
4. 보고서 = 해당 월 페이지 하위 페이지. 제목 `📊 Weekly Report | N월 M주차 (MM.DD–MM.DD)`.
5. 같은 주 일정표로 시간 보정 갱신 (`research-log/记忆本.md`).

구성 3섹션만 (다음 주 계획 없음):
1. 🏆 이번 주 핵심 성과 — 분야별 표
2. 🗓 일별 진행 내용 — 날짜/유형/내용 표
3. ✅ 다음 액션 완료 현황 — 표 + 완료율 콜아웃

## 미확인 사항 (사용자 확인 대기)

- 완료율 기준: 현재 "완료 체크 행 수 / 불가 제외 행 수" 가정.
- 알림 시간대: Asia/Seoul 가정 (Google Calendar 기본 시간대와 일치).
- 일요일 알림: 기본 알림 유지 (일정표에는 일요일 행 없음).
